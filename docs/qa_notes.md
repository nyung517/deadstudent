- Allowed feature set: 18 `NOMINAL_FEATURES` + 12 `NUMERIC_FEATURES` = 30. Design matrix after the fix below: `(2654, 235) (885, 235) (885, 235)`.
- `[c for c in design.feature_names if "2nd_sem" in c]` -> `[]` (0 columns).
- `[c for c in design.feature_names if "target" in c or "outcome" in c]` -> `[]`.
- Every design column maps back to one of the 30 allowed features; every allowed feature has >=1 design column (`unused: []`).
- Preprocessing is fitted on train only: `numeric__admission_grade` has train mean `-1.4e-15`, train std `1.0`, valid mean `-0.0014`; rebuilding train values from train mean/std gives max abs error `0.0`. `OneHotEncoder(handle_unknown="ignore")` is fitted on `split.train` only.

- DEFECT FOUND AND FIXED (see section 6): before the fix the design matrix had 233 columns and `daytime_evening_attendance` had zero columns - one of the 30 allowed features was silently dropped.

Verified true:

- `ai_log.md` numbers (2654 / 885 / 885, rates 0.3210 / 0.3220 / 0.3209, "4424 rows") -> match the observed run exactly.

Wrong or not runnable here:
- `uv sync` -> **fails**. Observed: scikit-learn 1.5.2 has no musl/cp312 wheel, uv falls back to the sdist and meson aborts with `ERROR: Unknown compiler(s): [['cc'], ['gcc'], ['clang'], ...]`, exit code 1. The same failure applies to `uv run python scripts/prepare_data.py` and `uv run python scripts/make_eda.py`, since they sync first. The documented quickstart does not work in this environment; `python3` from the sysroot is the working path. (Environment limitation, not a pin error - the repo cannot be blamed for the missing compiler.)
- README "4,424 students, 36 columns" -> the raw file has **37** columns (36 features + `target`); after `load_raw` the frame has 38 (`target` + derived `outcome`).
- README "Second-semester columns are excluded everywhere, so every feature is known before the second semester starts" -> **false as written**. `save_splits` writes the full normalised frame, so `data/processed/{train,valid,test}.csv` each have 38 columns including all 6 `curricular_units_2nd_sem_*` columns and `outcome`. Only the design matrix drops them. Safe for the current code path, but the sentence overstates what the CSVs contain and is a footgun for anyone modelling straight off `data/processed/`.
- README "Python 3.12 through uv" -> `.python-version` is `3.12` and `requires-python = ">=3.12"`, but this environment runs 3.14.10 and `uv sync` cannot complete anyway.

## 6. Defects

1. **Fixed (functional):** `normalise_columns` turned `Daytime/evening attendance` into `daytime/evening_attendance`, while `NOMINAL_FEATURES` expects `daytime_evening_attendance`. `build_design` uses `remainder="drop"`, so the column was dropped silently: 233 design columns, 17/18 nominal features, 29/30 allowed features used. Minimal fix: added `.replace("/", "_")` to the normalisation chain in `src/deadstudent/data.py`. After the fix: 235 design columns, 30/30 allowed features used, no 2nd-semester or label columns in `X`, determinism and split rates unchanged.
2. **Not changed (docs):** README claims 36 columns and "second-semester columns are excluded everywhere"; the CSV files keep all 6 second-semester columns (see section 5). Recommend rewording to "excluded from the design matrix" and "37 columns".
3. **Not changed (docs/env):** `uv sync` / `uv run ...` quickstart does not work without a C compiler. Recommend a note about the sysroot python or a musl-wheel-compatible pin.
4. **Observation:** `build_design` fails silently when a `feature_columns()` entry matches neither `NOMINAL_FEATURES` nor `NUMERIC_FEATURES` (the `remainder="drop"` behaviour that hid defect 1). Suggest asserting `set(columns) == set(nominal) | set(numeric)` so a rename can never again drop a feature quietly.
